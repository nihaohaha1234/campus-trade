# 校园二手交易平台演示流程

本文档用于项目展示和面试前复盘，按照用户使用路径和管理员管理路径说明系统核心功能。

## 1. 登录与注册

系统支持用户注册和登录。用户注册时需要输入用户名、密码和确认密码；登录成功后，前端会保存后端返回的 Token，并在后续请求中自动携带登录状态。

![登录页](<../photos/屏幕截图 2026-06-09 150132.png>)

![注册页](<../photos/屏幕截图 2026-06-09 150139.png>)

讲解要点：

- 后端使用 BCrypt 对密码进行加密存储。
- 登录成功后返回 JWT Token 和用户信息。
- 前端使用 Axios 请求拦截器自动携带 Token。
- Redis 用于记录登录失败次数，限制短时间内重复失败登录。

## 2. 商品浏览、搜索与热门商品榜

用户登录后进入商品列表页，可以浏览已上架商品，也可以根据关键词搜索商品。右侧展示热门商品榜，热门榜基于 Redis ZSet 记录商品访问热度。用户登录后，商品列表还会结合浏览记录进行轻量级个性化推荐，让用户最近感兴趣的同类商品更靠前展示。

![商品列表和热门榜](<../photos/屏幕截图 2026-06-09 150157.png>)

讲解要点：

- 商品列表只展示已上架商品。
- 商品列表和搜索结果都支持分页。
- 热门商品榜由 Redis ZSet 统计商品访问热度。
- 商品详情访问时会增加对应商品的热度分值。
- 登录用户访问商品详情时，会把浏览过的商品 ID 记录到 Redis List。
- 推荐接口会根据用户浏览过的商品标题和描述，组合推荐商品和普通商品，再进行统一分页。

## 3. 商品详情、收藏与发起交易

用户点击商品卡片进入商品详情页，可以查看商品图片、标题、价格和描述。用户可以收藏商品，也可以发起交易。

![商品详情页](<../photos/屏幕截图 2026-06-09 150217.png>)

讲解要点：

- 商品详情使用 Redis 缓存，减少重复查询 MySQL。
- 商品详情页会调用后端接口判断当前用户是否已收藏该商品。
- 收藏状态由后端返回的 Boolean 值决定，前端根据状态显示“收藏”或“已收藏”。
- 发起交易后会创建订单，并将商品状态修改为已锁定，避免重复交易。

## 4. 发布商品与图片上传

用户可以发布商品，填写标题、描述、价格并上传商品图片。图片上传后，后端将文件保存到本地目录，并返回可访问的图片路径。发布商品前，用户还可以调用 AI 优化商品标题和描述；真正提交发布时，后端会先调用 AI 做初步审核，AI 通过后再进入管理员人工审核流程。

![发布商品页](<../photos/屏幕截图 2026-06-09 150230.png>)

讲解要点：

- 前端使用 `FormData` 上传图片文件。
- 后端使用 `MultipartFile` 接收文件。
- 后端使用 UUID 重命名图片，避免文件名冲突。
- 商品发布后默认进入待审核状态，需要管理员审核后才会公开展示。
- AI 优化接口会根据标题、描述和价格生成更适合展示的商品文案。
- AI 审核接口在发布流程中自动触发，明显违规或无效的商品会直接被拒绝。
- AI 审核结果会写入审核日志表，方便管理员后续查看。

## 5. 我的商品管理

用户可以查看自己发布的商品，并按状态筛选，包括全部、待审核、已上架、已下架、已售出和已锁定。

![我的商品页](<../photos/屏幕截图 2026-06-09 150239.png>)

讲解要点：

- 我的商品接口根据当前登录用户 ID 查询数据。
- 用户 ID 来自后端解析 JWT 后保存的登录上下文，不直接相信前端传入。
- 用户只能查看和操作自己发布的商品。
- 修改商品后会重新进入待审核状态。

## 6. 收藏列表

用户可以在收藏列表中查看自己收藏过的商品，也可以取消收藏。点击收藏商品可以进入商品详情页。

![收藏列表页](<../photos/屏幕截图 2026-06-09 150248.png>)

讲解要点：

- 收藏表使用用户 ID 和商品 ID 建立关联。
- 数据库使用联合唯一索引限制同一用户不能重复收藏同一商品。
- 取消收藏后会刷新列表，当前页为空时会自动回到上一页。

## 7. 我的订单与订单详情

用户可以查看自己买到的订单和卖出的订单，并按订单状态筛选。订单详情页展示订单号、商品、价格、状态和创建时间，并根据当前用户身份和订单状态显示对应操作按钮。

![我的订单页](<../photos/屏幕截图 2026-06-09 150255.png>)

![订单详情页](<../photos/屏幕截图 2026-06-09 150305.png>)

讲解要点：

- 买家订单和卖家订单分别通过不同接口查询。
- 订单详情使用单个订单接口 `/orders/{orderId}` 查询。
- `type=buyer/seller` 用于前端判断当前视角，从而控制按钮显示。
- 卖家可以确认待确认订单。
- 买家或卖家可以完成已确认订单。
- 买家或卖家可以取消待确认或已确认订单。
- 创建、取消、完成订单时涉及订单表和商品表更新，需要事务保证一致性。

## 8. 管理员控制台

管理员登录后可以进入管理员控制台，管理商品、审核商品、管理用户、查看订单和查看 AI 审核日志。

![管理员控制台](<../photos/屏幕截图 2026-06-09 150318.png>)

讲解要点：

- 前端通过路由守卫限制普通用户访问管理员页面。
- 后端管理员接口会再次校验当前登录用户是否为管理员。
- 前后端都做权限判断，但真正的安全边界在后端。
- AI 审核日志页用于查看用户发布商品时的 AI 初审结果，包括商品标题、描述、价格、AI 建议、审核原因和创建时间。

## 9. 商品审核

管理员可以查看待审核商品，并选择通过或拒绝。审核通过后商品进入已上架状态；审核拒绝后商品进入下架或拒绝状态。

![管理员审核页](<../photos/屏幕截图 2026-06-09 150359.png>)

讲解要点：

- 新发布商品默认状态为待审核。
- 只有管理员可以调用审核接口。
- 审核成功后会刷新待审核列表。
- 如果当前页最后一个商品被审核掉，页面会自动回到上一页。

## 10. 用户管理

管理员可以查看用户列表，并对普通用户进行禁用或启用操作。

![用户管理页](<../photos/屏幕截图 2026-06-09 150406.png>)

讲解要点：

- 管理员可以禁用普通用户。
- 管理员不能禁用管理员账号。
- 用户被禁用后，即使旧 Token 仍然存在，也不能继续访问受保护接口。
- 登录拦截器会根据 Token 中的用户 ID 查询数据库中的用户状态。

## 11. 管理员订单管理

管理员可以查看全平台订单，并按订单状态筛选，方便追踪交易流程。

![管理员订单管理页](<../photos/屏幕截图 2026-06-09 150412.png>)

讲解要点：

- 普通用户只能查看自己作为买家或卖家的订单。
- 管理员可以查看全平台订单。
- 管理员订单页采用表格展示，适合批量查看和对比。
- 订单列表展示买家 ID、卖家 ID、商品、价格、状态和创建时间。

## 12. AI 审核日志

管理员可以查看用户发布商品时产生的 AI 审核日志。日志会记录发布用户、商品标题、商品描述、价格、AI 建议、审核原因和创建时间。

讲解要点：

- AI 审核不是替代管理员，而是作为发布前的第一层过滤。
- AI 审核通过后，商品仍然进入待审核状态，由管理员进行人工复核。
- AI 审核拒绝时，商品不会进入商品表，前端会提示拒绝原因。
- 审核日志可以帮助管理员复盘 AI 判断结果，也能作为项目中 AI 能力落地的展示点。

## 13. Railway 部署

项目已部署到 Railway，后端、前端、MySQL 和 Redis 都在云端运行。

讲解要点：

- 后端服务连接 Railway MySQL 和 Redis。
- 前端通过环境变量 `VITE_API_BASE_URL` 指向线上后端域名。
- 本地 `localhost:5173` 默认请求本地后端，线上前端请求 Railway 后端。
- Railway 上的图片上传当前保存到容器临时目录，适合演示；生产环境更适合接入对象存储。

## 14. 推荐演示顺序

正式演示时可以按照以下顺序操作：

1. 注册或登录普通用户。
2. 进入商品列表，展示搜索、分页、热门商品榜和推荐商品。
3. 进入商品详情，演示收藏和发起交易。
4. 进入收藏列表，演示取消收藏。
5. 发布一个商品并上传图片，演示 AI 文案优化和 AI 初审。
6. 切换管理员账号，进入管理员控制台。
7. 审核刚发布的商品。
8. 进入 AI 审核日志页，查看刚才发布商品产生的 AI 审核记录。
9. 回到普通用户商品列表，查看商品已上架。
10. 发起交易，进入订单列表和订单详情。
11. 切换卖家视角确认订单。
12. 完成订单。
13. 管理员查看订单和用户管理页面。

## 15. 面试讲解重点

项目可以重点讲以下内容：

- 前后端分离架构：Vue 前端通过 Axios 调用 Spring Boot 后端接口。
- 登录认证：JWT + 拦截器实现接口保护。
- 密码安全：BCrypt 加密存储密码。
- 权限控制：普通用户和管理员权限分离，前端路由守卫和后端接口校验结合。
- Redis 应用：登录失败限制、商品详情缓存、热门商品榜。
- 个性化推荐：使用 Redis 记录用户浏览记录，并结合商品标题和描述做轻量推荐。
- AI 接入：调用 DeepSeek API 做商品文案优化和发布前审核。
- AI 审核日志：记录 AI 审核结果，管理员可查看审核建议和原因。
- 商品审核机制：用户发布商品后需要管理员审核，避免商品直接公开。
- 订单状态流转：待确认、已确认、已完成、已取消。
- 数据一致性：订单创建、取消、完成涉及商品状态变化，使用事务保证一致性。
- 文件上传：图片上传后返回可访问路径，商品保存图片 URL。
- 分页查询：商品、收藏、订单、用户、管理员列表均支持分页。
- 云端部署：前端、后端、MySQL、Redis 部署到 Railway，形成线上访问闭环。
